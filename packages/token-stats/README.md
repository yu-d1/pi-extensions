# @liziy/token-stats

pi 的 Token 用量与配额监控扩展。footer 实时显示 token 累计、缓存命中率、输出速率、上下文占用与套餐配额，`/stats` 可按日/小时/周/月/年回看，并支持按模型归类统计。零运行时依赖，不上传任何数据。

## 安装

```bash
pi install npm:@liziy/token-stats
```

## 使用

**1. 启用套餐配额**：`/stats` → `套餐配额配置`，为当前 provider 选择对应套餐，footer 立即显示。

| 套餐 | 适用 provider | 凭据 |
|------|--------------|------|
| MiniMax (Coding Plan) | `minimax_local` / `minimax-cn` / `minimax` | `MINIMAX_API_KEY` |
| GLM (智谱) | `zhipu-cn` / `zhipu` / `glm` / `bigmodel` | `GLM_API_KEY` |
| Kimi (Coding Plan) | `moonshot-cn` / `moonshot` / `kimi` | `MOONSHOT_API_KEY` 或 OAuth |
| DeepSeek | `deepseek-cn` / `deepseek` | `DEEPSEEK_API_KEY` |
| mimo（小米） | `mimo` | 浏览器登录（见下） |
| Command Code (GO 套餐) | `commandcodego` | pi `/login` 登录 |

凭据读取顺序：环境变量 > `~/.pi/agent/auth.json` 中当前 provider 的 `key` / OAuth `access`。

> **mimo** 需从控制台网页读取，没有 API Key。首次启用会弹出 Chrome 窗口，在窗口内扫码登录即可，扩展自动读取 Cookie 并优雅关闭窗口。登录一次后小米 SSO 凭据会保存约 30 天，此后续期由无头模式静默完成（约每天一次），不会再弹窗。需本机有 Chrome / Edge / Chromium。

**2. 配置状态栏**：`/stats config`，可勾选显示项、调整精度与样式，改完立即生效。

**3. 查看统计**：

```bash
/stats                       # 主菜单
/stats day [YYYY-MM-DD]      # 日统计
/stats hour [YYYY-MM-DD]     # 小时分布
/stats week|month|year       # 周 / 月 / 年
/stats models [from] [to]    # 按模型归类（默认近 7 天）
/stats html                  # 生成网页报表，输出可点击链接
/stats clear                 # 清除历史统计数据
```

## 网页报表

菜单「统计查询」或 `/stats html` 打开网页报表，终端输出可点击链接。

- **模板固定、数据旁路**：`report.html` 随包发布、永不改写；数据写在同目录的
  `report-index.js`（字典 + 日期列表，几百字节）和 `report-day-YYYY-MM-DD.js`（单日逐轮记录）。
  链接始终不变，可以收藏。
- **索引 + 分片**：首次生成会一次性写好索引和全部历史分片（约 30~200 ms）；
  之后每轮对话结束自动重建**当天**分片（几毫秒），历史分片永不再算。
  所以日常对话产生的数据不需要手动执行命令，点页面上的「刷新数据」即可看到。
- **页面内切区间**：日期栏的 `当天 / 近 7 天 / 近 30 天 / 近 90 天` 与自定义起止日期都是前端过滤，
  切换时按需加载对应日期的分片，不需要重新生成。
  分片用 `<script src>` 注入而非 `fetch`（`file://` 下 `fetch` 会被 CORS 拦死）。
- **内容包括**：总览卡片、按模型占比、逐日趋势（prompt token 面积 + 命中率副轴，悬停看单日明细）、
  按月用量热力图（可翻月，悬停看当日用量）、分页逐轮明细（可搜索、排序、跳页）。
- **点击联动**：点汇总里的模型行筛该模型，再点取消；明细表内点**时间**只看那一天，
  点**模型**只看该模型。所有筛选都作用在整页统计上。
- **命中率不跨模型混算**：总览的混算值会提示“无工程意义”，每个模型、每个热力格、每行明细均用各自口径。
  明细的「累计」列按**模型各自**累加——跨模型混加会让某模型首轮继承别的模型几百轮的高命中率
  （曾把真实 2.76% 显示成 95%）。
- **刷新明细**：「逐轮明细」工具栏的刷新按钮只重读当前区间的分片、重算下方列表，
  不重载索引、不动模型筛选与日期区间。
- **换模型不需改模板**：模型名、数量全部从数据动态读取，新增模型自动出现。
- 终端点击需 `Ctrl+click`（macOS 为 `Cmd+click`）；不支持超链接的终端请手动复制打印出的路径。
- 日期栏的快捷区间 + 自定义起止日期已覆盖日/周/月/年所有查询维度，终端不再另列表格入口。

### 本地服务与定时统计

菜单「统计查询」时会在 `127.0.0.1:7788` 拉起一个本地服务并开始**每 1 分钟**自动统计，
页面右上角显示服务状态。

- **为什么需要服务**：报表是 `file://` 静态页，网页自身无法创建进程。
  「启动/停止定时统计」这类动作必须有个活着的进程接住，因此服务运行在 pi 进程内。
  pi 关掉后服务随之消失，页面显示「未连接」，只能看已有数据。
- **右上角面板**：
  - 状态灯 + 状态字（运行中 / 已停止 / 统计出错 / 未连接）
  - 上次统计时间与距今、轮数、耗时；下次执行时间与间隔
  - `暂停自动统计 / 开启自动统计`：总开关。关闭后定时器与「每轮对话后自动重建」
    一起停，对话不会写入报表
  - 间隔下拉：1 / 5 / 15 / 30 / 60 分钟
  - `立刻统计`：手动跑一次，**不受自动开关限制**（暂停状态下仍可用）
  - `停止服务`：真正释放 7788 端口。之后页面显示「未连接」，
    需要回 pi 执行「统计查询」重新拉起
- **端口占用**：7788 被其它程序占用时会提示，此时页面显示「未连接」，不影响报表阅读。
- **只监听回环**：仅绑定 `127.0.0.1`，并校验 `Origin`（允许 `file://` 的 `null` 与本机地址），
  其它来源一律 403。

## 清除统计数据

菜单「清除历史统计」或 `/stats clear`，可选最近 7 / 30 / 90 天、指定区间或全部历史。

- **三层同步删除**：`raw` 逐轮明细、`hourly` 小时聚合、`daily` 日聚合一起清，
  避免同一段时间在网页报表与终端视图里显示成两组数字。
- **删前先给明细**：确认框会列出区间、涉及天数、各类文件数与合计体积，不可撤销。
- **为什么不在网页里做**：报表是 `file://` 本地页面，浏览器无法删除磁盘文件；
  要让按钮真正生效需额外起一个本地服务，为一个低频操作不划算，因此入口放在 pi 里。

## 缓存命中率与模型切换

服务端 KV Cache 按 `provider + model` 隔离，因此统计按模型分桶：

- footer 的 `↓ ↑ Σ CH` 只统计**当前模型**：切换模型后显示的是该模型自己的数（刚切到的新模型为 `↓0 ↑0 Σ0 CH 0.0%`）。
- 命中率口径统一为 `cacheRead / 总输入`，加权计算，不是各轮求平均。
- **自动识别 provider 的 input 口径**：多数 provider 的 Anthropic 兼容端点把 `input` 报成「已含缓存的总量」，
  与 pi-ai 的「input 是纯新增」假设相反。若不做区分，缓存会被算两遍，命中率被钉在 50% 左右
  （实测某模型真实 99%，显示却是 49.9%）。扩展在落盘时按「`cacheRead` ≈ 上一轮 `input`」判定口径并记录，
  老记录在读取时现场推断，两种口径都能给出正确结果。
- 累计命中率尚可但最新一轮骤降时，`CH` 变红并附 `↓单轮命中率`，提示前缀缓存断了。
- `/stats` 的模型维度直接从逐轮明细（`raw/`）现算，不依赖日聚合累积，任何区间随时可查。
- 时间报表在多模型的时间段下会列出 `↳ 模型` 明细行，各自独立计算命中率；跨模型汇总行不显示命中率。
- 旧版本日志没有模型字段，统一归入 `unknown/legacy` 桶；若整个区间都缺模型信息会单独提示。
- 切换模型不影响对话上下文：pi 的历史消息原样带给新模型（本扩展只统计用量，不干预上下文）。
