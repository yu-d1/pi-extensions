# context-fold

让长对话不再吃爆上下文。会话变长后，较早的对话会被压缩成摘要，原文一条不丢，需要时随时取回。

## 安装

```bash
pi install npm:@liziy/context-fold
```

重启 pi 生效。

## 快速上手

装上就能用，不需要配置。

1. 正常对话，什么都不用管
2. 上下文变长后，插件在后台自动生成摘要
3. 较早的对话被折叠成一段，原文保留
4. 想看压了多少：`/fold s`

AI 会看到这样的标记：

```
[历史摘要 b2 · 覆盖 37 条消息]

修复了登录超时问题，改动在 src/auth/login.ts:88。
决定不引入重试库，因为现有代码已有退避逻辑。

需要原文时调用 recall("b2")。
```

## 命令

`/fold` 打开菜单：状态 / 设置

| 子命令 | 说明 |
|--------|------|
| `/fold s` | 查看上下文占用、已折叠的块、节省了多少 |
| `/fold f` | 立即折叠 |
| `/fold c` | 查看并修改设置 |
| `/fold reset` | 恢复默认设置 |

折叠进行时，状态栏会短暂显示 `折叠中...` 或 `待生效`，其余时候不占位。

## 设置

`/fold c` 打开：

| 设置项 | 默认值 | 可选值 |
|--------|--------|--------|
| 启用折叠 | 是 | 是 / 否 |
| 触发方式 | 按阈值 | 按阈值 / 模型判断（未测试） |
| 触发阈值 | 150K | 50K / 100K / 150K / 200K / 自定义 |
| 保留最近 | 20K | 10K / 20K / 40K / 自定义 |
| 保底触发 | 90% | 关闭 / 80% / 90% / 95% / 自定义 |

**启用折叠**：总开关，关掉后什么都不做。

**触发方式**：选「按阈值」就到设定 token 数自动折；选「模型判断」就交给 AI 自己决定。两者互斥，选模型判断后触发阈值不再显示。

**触发阈值**：上下文到多少 token 时折叠。默认 150K。

**保留最近**：最近多少 token 的原文不动。这部分正要用，压掉会影响判断。默认 20K。

**保底触发**：最后一道防线。不管用哪种触发方式、AI 有没有主动折叠，到设定占比就强制折。默认 90%，填 0 关闭。

## AI 工具

| 工具 | 用途 |
|------|------|
| `recall` | 取回折叠块原文。块大时可按关键词筛选（`query`）或分段读（`offset`） |
| `request_fold` | 请求折叠（仅模型判断模式） |
| `fold_status` | 查看上下文构成与折叠情况 |

`request_fold` 有两个可选参数：

| 参数 | 作用 |
|------|------|
| `focus` | 告诉摘要器这段历史里哪些结论、路径、决定必须留住 |
| `includeRecent` | 刚结束的那几轮已经收尾，把它们也一起折掉 |

## 配置文件

`~/.pi/agent/context-fold-config.json`，设置 `PI_CODING_AGENT_DIR` 可改变目录。

折叠记录写在会话文件里，重启或切换分支都能恢复。

## 和 /compact 的关系

两者可以共存，互不冲突。

| | context-fold | `/compact` |
|---|---|---|
| 原文 | 保留，可召回 | 丢弃 |
| 可逆 | 是 | 否 |

## 限制

- AI 模型不可用时折叠会失败，连续失败 3 次后暂停
- 召回按 30K 字符一段返回，超大块需要翻几次才能读完（可用 `query` 只取相关的）
- 单轮对话本身就超过阈值时，那一轮无法折叠
