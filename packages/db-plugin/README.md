# @liziy/db-plugin

让 AI 直接查询你的数据库（PostgreSQL / MySQL / Oracle）。配好连接后，AI 知道你有哪些库、哪些表、表里有什么字段，不用你复制粘贴 SQL、也不用切换工具。

## 安装

```bash
pi install npm:@liziy/db-plugin
```

重启 pi 生效。

## 快速上手

1. `/db` → `编辑` → `新增连接`
2. 依次填：数据库类型 → 主机 IP → 端口 → 库名（可留空）→ 账号 → 密码 → 连接名称
3. 保存时会自动测试连通性，失败会问你是否仍要保存
4. 保存后询问是否立即启用库，选是 → 勾选要开放给 AI 的库
5. 直接跟 AI 说「查一下 jetlinks 里最近 10 条设备记录」

## 命令

`/db` 不带参数会打开菜单：

```
数据库管理
──────────────
启用
编辑
查看
删除
设置
```

| 菜单项 | 作用 |
|--------|------|
| 启用 | 开关连接本身，以及该连接下哪些库对 AI 开放 |
| 编辑 | 选择已有连接修改，列表底部可新增连接 |
| 查看 | 列出所有连接，含账号密码，便于核对 |
| 删除 | 删除连接，二次确认 |
| 设置 | 只读模式 / 最大行数 / 查询超时 |

也支持子命令直接进入：

| 子命令 | 说明 |
|--------|------|
| `/db enable` | 启用连接或库 |
| `/db edit` | 编辑连接（可新增） |
| `/db view` | 查看所有连接及账号密码（别名 `ls`） |
| `/db rm` | 删除连接 |
| `/db config` | 查看与修改设置 |
| `/db reset` | 恢复默认设置 |

## 连接与库

**一个连接 = 一台数据库服务器，下面可以有多个库。**

比如同一个 PostgreSQL 实例上有 `jetlinks`、`gt_cloud`、`gt_quartz` 三个库，只需要配一个连接，然后在这个连接里勾选要开放的库，不必建三条连接。

- 新增连接时库名**可以留空**，保存后自动扫描服务器上有哪些库
- 也可以只启用其中一部分库，未启用的库 AI 看不到
- Oracle 例外：必须填服务名，且一个服务名就是一条连接

### 启用界面

`/db` → `启用` → 选择连接，进入勾选界面：

```
────────────────────────────────────────────────────────────
启用 - pg79-5432
勾选的库对 AI 开放
搜索框输入新库名后回车可新增；空格切换，^a 全选，^s 保存

> 搜索或输入新库名…

→ ✓ 连接本身  192.168.250.79:5432
  ✓ jetlinks
  ✓ gt_monitor
  ✓ gt_cloud
  ✓ gt_quartz
  ✗ gt_cloud_nacos
  ✗ postgres
  ✗ wvp

  空格 切换 · ^a 全选 · ^x 清空 · ^s 保存 · esc 完成 · 已启用 4/7
────────────────────────────────────────────────────────────
```

按键：

| 按键 | 作用 |
|------|------|
| `↑` `↓` | 移动光标（首尾循环） |
| `空格` / `回车` | 切换勾选 |
| 输入字符 | 实时模糊搜索 |
| 输入新库名 + `回车` | 新增一个库并自动勾选 |
| `^a` | 全选 |
| `^x` | 清空（至少保留一个库） |
| `^s` | 保存，**留在界面**继续调整 |
| `esc` | 完成；有未保存修改时需再按一次确认放弃 |

「连接本身」置顶，可以整体停用；停用后该连接下所有库都不对 AI 开放。**始终至少保留一个启用的库。**

### 编辑连接

每项都会显示当前值，`回车` 保持原值，输入新内容则覆盖，输入 `-` 置空：

```
地址: 192.168.250.79:5432
账号（当前: postgres，回车保持，输入 - 置空）
```

改了地址、端口、账号或密码会自动重新测试连接；只改名称或说明则跳过测试。

## 设置

`/db` → `设置`：

| 设置项 | 默认值 | 可选值 |
|--------|--------|--------|
| 只读模式 | 是 | 是 / 否 |
| 最大行数 | 500 | 1 / 50 / 500 / 不限制 / 自定义输入 |
| 查询超时 | 15s | 正整数秒数 |

**只读模式**开启时 AI 只能执行查询，`INSERT`、`UPDATE`、`DELETE`、DDL 都会被拒绝。

无论只读模式是否开启，`DROP TABLE`、`DROP DATABASE` 等删除结构的语句**始终禁止**。

当前策略会在每轮对话注入系统提示，AI 不会误判自己的权限。

## AI 会用到什么

扩展注册了三个工具，AI 会自动调用：

| 工具 | 用途 |
|------|------|
| `list_tables` | 列出表与视图，含表注释 |
| `describe_table` | 查看列名、类型、可空、默认值、主键、列注释 |
| `query_database` | 执行 SQL |

**`database` 参数格式**：

- `连接名/库名` —— 如 `pg79-5432/gt_cloud`，适用于任何情况
- `连接名` —— 仅当该连接下**只有一个**启用的库时可省略库名

`list_tables` 传连接名（不带库名）时会**一次列出该连接下所有启用库的表**，每段用 `【连接/库】` 分隔，适合先摸清全貌。

普通对话不需要手动调用，直接说需求即可：

> 「gt_cloud 库里设备表有哪些字段？」
> 「统计 jetlinks 最近一周每天的数据量」
> 「把 gt_quartz 的定时任务表结构导出来给我」

## 配置文件

| 文件 | 内容 |
|------|------|
| `~/.pi/agent/db-configs.json` | 连接列表（**密码明文保存**） |
| `~/.pi/agent/db-plugin-config.json` | 只读模式、最大行数、查询超时 |

设置 `PI_CODING_AGENT_DIR` 环境变量可改变上面的目录。

> 密码是明文存储的，请确认该文件权限。不要把 `db-configs.json` 提交到版本库。

## 版本历史

- **3.0.0** — 一条连接支持多个库、独立的启用勾选界面、库名可省略；自动迁移 2.x 配置
- **2.2.3** — 系统提示注入可用数据库列表，AI 不再猜连接名称
- **2.2.0** — `/db` 菜单新增编辑与删除确认
- **2.1.0** — 执行确认改为交互式确认框
- **2.0.0** — 迁移到 Node.js 驱动，移除 Python 依赖
- **1.0.0** — 首个版本：PostgreSQL / MySQL / Oracle 连接管理与查询工具

## 限制

- 每次查询新建连接、用完即关，不维护连接池。局域网通常多 5–20ms 握手开销
- `oracledb` 依赖原生模块，Windows 上如安装失败需先装 Instant Client
